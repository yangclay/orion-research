# 用户调研模式：差距分析（Gap-vs-Existing Pattern）

> 来源：2026-05-14 Claude Code skill creator 调研
> 适配：orion-research skill v3.1（Step 1 识别 → Step 3 补证据 → Step 5 落结论）

## 模式描述

用户的调研问题往往不是"X 是什么"，而是**"X 和我们已有的有什么本质区别"**。

典型追问链：
1. "调研一下 X" → 初始搜索
2. "有没有现成成熟的？" → 搜索现有方案
3. "实际有什么惊艳的提升？" → 要求区分"真正有价值的" vs "表面功能"
4. "有什么区别？" → 要求和现有能力做对比

## 触发识别（Step 1 拆解时判断）

问题含以下任一信号 → 判定为**差距型调研**，走本模式：

- "X 和 Y 有什么区别 / 相比 X 有什么优势 / 有什么提升"
- "有没有现成的 / 现成方案已经能做什么 / 市面上有没有成熟的"
- "X 的真正价值是什么 / 本质区别是什么"
- 提问者是用户（历史追问链特征，见反面教材）

## 应对（v3.1 落点）

| 步骤 | 动作 |
|------|------|
| **Step 1 拆解** | 固定加入一个子问题：**"现有方案已经能做什么？X 的真正增量是什么？"**——不等用户追问才做对比 |
| **Step 3 Gap Analysis** | 证据缺口不仅指"找不到来源"，也包括**"只有 X 的介绍、没有与现有方案的对比"**——发现此类缺口 → 补搜对比类查询（"X vs Y"、"X alternative"） |
| **Step 5 报告** | 核心结论**第一条**必须是：X 的真正价值（解决的痛点，不是功能列表）+ 和现有方案的差距（X 能做而现有方案做不到的） |

## 反面教材

2026-05-14 调研前半段堆了很多功能对比表，但没有提炼核心洞察。直到用户追问"实际有什么惊艳的提升"，才总结出：

> "创建 skill 不是问题，衡量和迭代 skill 才是真正差距。"

这句话应该在第一轮报告里就有。教训：**报告第一条结论不是"X 有哪些功能"，而是"X 解决了什么痛点、相比现有方案增量在哪"。**

**正面案例（2026-08-13 实测）：** AI 营销 Agent 工具对比调研，核心结论第一条直接给差距——"n8n vs Zapier 存在约 90% 的成本差距"（同一 5 步工作流跑 1000 次：Zapier $500+/月，n8n $20/月），而不是罗列各工具功能表。
