# 故障处理（Failure Handling）

## F1：web_search 零结果

**触发条件：** `web_search` 返回空 / 覆盖率过低

**一线修复：** 换同义词重搜（中英文各一次），或升级到 Tavily（内联 `search_depth=advanced`）

**兜底方案：** 降级到 `web-fetch.sh` + 手动 `curl` 已知权威来源

## F2：Tavily 配额耗尽

**触发条件：** Tavily API 返回 429/quota error

**一线修复：** 切到 SerpAPI 或继续用 `web_search`（免费层）

**兜底方案：** 在报告标注"⚠️ Tavily 不可用，覆盖度可能不足"，继续用免费源完成

## F3：web_fetch 被拦截

**触发条件：** 返回 403 / 空内容 / Cloudflare challenge

**一线修复：** 用 `scripts/scrape-stealth.py --mode stealth` 重试

**兜底方案：** 用 TinyFish Fetch（见 `references/tool-reference.md`）或标注"来源不可抓取，仅用摘要"

## F4：Context window 溢出

**触发条件：** 搜索结果总量 > 70% context budget

**一线修复：** 只保留去重后 top-20 来源的摘要（非全文），全文写入中间文件

**兜底方案：** 分批处理：先处理子问题 1-3，写中间文件；再处理 4-5，合并

## F5：核心结论全为 C/D 可信度

**触发条件：** Step 4 验证后无 A/B 级结论

**一线修复：** 回到 Step 3 定向补搜（换 query、加 site: 过滤）

**兜底方案：** 在报告显式标注"⚠️ 核心结论证据不足，需人工判断"，不编造可信度

## F6：Gap Analysis 显示缺口无法补齐

**触发条件：** 补搜 3 轮后仍有子问题无可靠证据

**一线修复：** 回溯最弱维度（通常是覆盖度或来源质量），换引擎组合再搜

**兜底方案：** 告知 用户 "当前质量待提升"，给出已完成的部分报告 + 建议补充方向

## F7：来源严重矛盾

**触发条件：** ≥2 个权威来源对同一事实说法相反

**一线修复：** 查原始出处（论文/官方文档/一手数据），标注哪方更可信

**兜底方案：** 并列呈现双方说法 + 矛盾原因分析，标注"需人工裁决"

---

## 执行原则

- F1-F3 是搜索层故障，自动修复不中断
- F4-F5 是质量层故障，修复后继续
- F6-F7 是交付层故障，必须告知 用户
